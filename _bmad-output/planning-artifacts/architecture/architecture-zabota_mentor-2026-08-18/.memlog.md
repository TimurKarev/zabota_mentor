- (decision) AD-1 pipeline-not-agent: deterministic engines compute all money/scores/bars/recommendations; LLM only rephrases pre-computed facts into psychotype-calibrated prose. Binds every module; prevents LLM-hallucinated figures violating honesty-in-numbers (BRD §15, §11.5) and makes LLM outage degrade wording, not correctness.
- (decision) AD-2 ports-and-adapters: every external system behind a Protocol port (LlmPort, CrmPort, TelegramPort, Clock, ConfigStore); domain layer framework-agnostic, no external calls from domain. Prevents provider lock-in and untestable engines; Clock injectable makes quiet-hours/DST logic unit-testable.
- (decision) AD-3 CRM anti-corruption layer: Mentor owns canonical model (Master, Client, Appointment, Visit, Payment/CheckLine); Zabot/YClients concepts translated at the boundary, never leaking into engines. Watermark polling is the sync baseline; webhooks only ever an accelerator. Prevents CRM-vendor coupling while the surface facts are owner-dependent.
- (decision) AD-4 Postgres is the durability backbone: every outbound side effect goes through the transactional outbox; scheduler = scheduled_messages + due-row sweep (FOR UPDATE SKIP LOCKED); Redis holds only dedup/pacing/hot cache, never source of truth. Prevents dual-write loss and divergent scheduling implementations.
- (decision) AD-5 two-zone residency [ADOPTED by owner 13.08.2026]: all PDn stored and primarily processed in RU zone (Yandex Cloud); LLM calls leave only via the depersonalization gateway (direct identifiers stripped inside RU zone) through a foreign egress point; art.12 consent + Roskomnadzor notification are launch gates. Prevents 152-FZ ч.5 ст.18 violation and per-caller enforcement drift.
- (decision) AD-6 insert-only versioned config: business parameters (quiet hours, caps/floors, trigger offsets, scheme coefficients, freshness tiers, score weights, thresholds, hysteresis, smoothing alphas) live in immutable versioned rows; every message and score row stores config_version used; engines read config by version at decision time; rollback = activating a prior version. Prevents unreproducible decisions and mid-message config drift.
- (decision) AD-7 salon-scoped tenancy from day one: every domain row carries a salon key; cross-salon isolation enforced at query layer. Prevents a schema rewrite when the owner answers the isolation/role-access open question (retrofitting multi-tenancy is a rewrite).
- (decision) AD-8 time model: all timestamps stored UTC in Postgres; salon/master timezone applied at render; quiet hours and pre-visit offsets evaluated at send-decision time against the master's local clock, never baked into job fire time. Prevents 23:00 messages across RU's 11 static zones.
- (decision) AD-9 degradation ladder: per-entity freshness tiers (checks ≤60min, schedule ≤15min, dynamics ≤24h); level 1 = labeled stale data, no monetary forecasts; level 2 = communication without figures; post-recovery resync recomputes totals and never backdates event messages. Prevents each engine inventing its own stale-data behavior.
- (decision) AD-10 dispatcher owns arbitration and pacing: competing triggers resolved by expected-income priority (defer/merge); frequency caps (≤5/shift, ≤2/day-off) AND floors (message-class disable ladder, money class last) plus per-chat token-bucket pacing enforced in the dispatcher, never in prompts. Prevents per-module spam logic drift.
- (decision) AD-11 modular monolith boundaries: one deployable, modules (crm_sync, profile, engines, messaging, llm, config) call each other only through published interfaces; zero shared table access across modules; one Postgres schema per module + append-only audit schema. Prevents distributed-monolith ops tax while keeping extraction possible.
- (decision) AD-12 at-least-once everywhere: Telegram updates deduped on update_id; outbox rows and sync jobs idempotent by natural key. Prevents double-send/double-count on redelivery.

- (decision) AD-16 new (output validator — hard enforcement of figure determinism at egress): a named validator component sits on the message egress path AFTER LLM re-personalization and BEFORE the outbox send. For every money-type number in the rendered message it checks byte-equality (after engine-defined rounding) against the corresponding engine-computed value from RenderFacts. On mismatch: the message is NOT sent (hard fail), the event is audited (message_id, mismatched field, expected vs actual), and a deterministic template fallback is queued for the same outbox row (wording degrades, correctness never does — same principle as LLM outage). The validator is owned by the messaging module (it is the egress gate of the pipeline-not-agent invariant); it runs inside the RU zone; it is unit-tested + covered by golden tests. Binds AD-1; prevents any LLM-authored/rounded/extra number reaching the master — the structural guarantee behind CM-4 (zero figure-accuracy incidents).
